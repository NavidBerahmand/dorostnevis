# textlint-rule-preset-farhangestan

قواعد **دستور خطّ فارسی (ویراست دوم، فرهنگستان زبان و ادب فارسی، ۱۴۰۴)** برای [textlint](https://textlint.org).

این پیش‌تنظیم متن فارسی را می‌خواند، خطاهای املایی و فاصله‌گذاری را گزارش می‌کند و بیشترشان را خودکار اصلاح می‌کند. کنار هر پیام، بند و صفحهٔ دستور خط آمده است.

الگوی ساختار: [textlint-rule-preset-JTF-style](https://github.com/textlint-ja/textlint-rule-preset-JTF-style)؛ هر بند راهنما یک قاعده، و مثال‌های خود کتاب آزمون قاعده‌اند.

## نمونه

```
قبل: رييس اداره گفت كه این مساله را بررسي می کنیم و نتیجه ی آن را اعلام می کنیم.
بعد: رئیس اداره گفت که این مسئله را بررسی می‌کنیم و نتیجۀ آن را اعلام می‌کنیم.
```

## نصب و استفاده

```sh
npm install --save-dev textlint textlint-rule-preset-farhangestan
```

`.textlintrc.json`:

```json
{
  "rules": {
    "preset-farhangestan": true
  }
}
```

```sh
npx textlint متن.md          # گزارش
npx textlint --fix متن.md    # اصلاح خودکار
```

### گزینه‌ها

```json
{
  "rules": {
    "preset-farhangestan": {
      "plural-ha": { "mode": "required-only" },
      "ezafe-he": { "style": "he-hamza", "model": false },
      "normalize-characters": { "digits": false },
      "lexicon": { "dictionaries": { "hamza": false } }
    }
  }
}
```

- `plural-ha.mode`: `recommended` (پیش‌فرض؛ جدانویسی توصیه‌شدهٔ کتاب) یا `required-only` (فقط موارد الزامی، مثل «خانه‌ها»).
- `ezafe-he.style`: `he-yeh` (پیش‌فرض، «ۀ» مثل خود کتاب) یا `he-hamza` («هٔ»).
- `ezafe-he.model`: `false` مدل کسرهٔ اضافه را خاموش می‌کند.

## مدل کسرهٔ اضافه

اینکه کلمه‌ای مثل «خانه» در حالت اضافه است («خانۀ قبلی») یا نه («خانه بزرگ است») را قاعده نمی‌تواند بگوید. یک مدل رگرسیون لجستیک کوچک (۵۳۶ کیلوبایت، در مرورگر اجرا می‌شود) از روی کلمه‌های اطراف و نقش دستوری‌شان حدس می‌زند.

- **داده:** مقاله‌های ویکی‌پدیای فارسی (CC BY-SA) که کسرهٔ اضافه را با «هٔ» می‌نویسند؛ فقط مقاله‌هایی که این کار را یکدست کرده‌اند (۶۰۰۶ مقاله، ۲۶۰ هزار نمونه). برچسب‌ها از خود متن می‌آیند و کسی دستی برچسب نزده است.
- **تنظیم اطمینان:** ویکی‌پدیا بخشی از کسره‌ها را ننوشته، برای همین مدل خام بیش از حد محتاط بود. اطمینانش روی دو مجموعهٔ تمیز تنظیم شد: متن خود دستور خط (۸۴۲ مورد، همهٔ کسره‌ها با «ۀ») و ۳۰۰ مورد تصادفی از ویکی‌پدیای بی‌نشانه که دستی برچسب خورده‌اند (`hand-labels.jsonl`؛ در آموزش نبودند).
- **نتیجه در آستانهٔ ۹۰٪:** دقت ۹۴ تا ۹۶٪ و پوشش ۴۸ تا ۶۵٪ کسره‌های واقعی (هر مجموعه با تنظیمِ مجموعهٔ دیگر سنجیده شد). پیش از تنظیم، پوشش در همین آستانه ۱۵ تا ۲۳٪ بود.
- **اصلاح خودکار** از ۹۰٪ اطمینان به بالا و برای کلمه‌های شناخته‌شده؛ بین ۶۰ تا ۹۰٪ فقط پیشنهاد.
- **بررسی دستی اصلاح‌های خودکار:** ۱۵۰ اصلاح خودکار تصادفی روی متن تازهٔ ویکی‌پدیا دستی بررسی شد (`hand-labels-fixes.jsonl`): ۱۴۴ درست (۹۶٪). خطاها: ترکیب‌هایی که با فاصله نوشته شده‌اند («جامعه شناسان»)، «۳ دوره قهرمان» و متن خراب.
- **ترکیب‌های با فاصله:** اگر دو کلمه با هم ترکیب شناخته‌شده‌ای بسازند («جامعه شناسان» ← «جامعه‌شناسان»)، به‌جای کسرهٔ اضافه همان ترکیب پیشنهاد می‌شود.
- **ساختن دوباره:** `scripts/ezafe-model/` (`extract_wiki.py`، `build_pos.py`، `train.py`، سپس `calibrate.py`).

## مدل «را»ی چسبیده

«کتابرا» ← «کتاب را»؛ ولی «لورا»، «نورا» و «کاپرا» نام‌اند. ویکی‌پدیا «را» را همیشه جدا می‌نویسد، پس هر کلمهٔ مختوم به «را» در آن یک واژه (معمولاً نام) است و نمونهٔ منفی می‌شود؛ نمونه‌های مثبت از چسباندن «X را» ساخته می‌شوند. مدل ۲۴ کیلوبایت است (`train_ra.py`).

- روی مقاله‌های کنارگذاشته: دقت ۹۹٪ در آستانهٔ ۹۰٪.
- روی سه بخش ۱٫۵ مگابایتی ویکی‌پدیا که همهٔ «را»هایش را چسباندیم: بیش از نیمی خودکار اصلاح شد و هیچ نامی («لورا»، «گندهارا»…) خودکار شکسته نشد.
- اصلاح خودکار از ۹۰٪ و فقط پس از اسم‌های پرکاربرد؛ بقیه پیشنهاد. ضمیرها («خودرا»، «شمارا») در فهرست‌ها هستند؛ «مارا»، «تورا» و «اورا» چون ممکن است نام باشند فقط پیشنهادند. `test/ezafe-model-test.ts` بررسی می‌کند که نسخهٔ TypeScript دقیقاً همان امتیازهای Python را بدهد.
- `lexicon.dictionaries`: هر فهرست (`multiSpelling`، `compounds`، `hamza`) را می‌شود خاموش کرد.

## اصل طراحی: دقت مهم‌تر از پوشش

پیشنهاد غلط از پیشنهاد جاافتاده بدتر است. برای همین:

- شکل پیوسته («میرود»، «بیدلیل»، «بزرگتر») فقط وقتی اصلاح می‌شود که خود کلمه در واژه‌نامهٔ Hazm نباشد و شکل درستش باشد. برای همین «میدان»، «میلاد»، «بیمار»، «دفتر» و «دیمیتری» دست نمی‌خورند. این بررسی روی همهٔ واژه‌های Hazm اجرا شده و هیچ واژهٔ درستی را عوض نمی‌کند.
- استثناهای کتاب همیشه بر داده‌های Hazm مقدّم‌اند (Hazm «بی‌هوش» و «بی‌عار» دارد، کتاب «بیهوش» و «بیعار»).
- «تر» فقط وقتی «از» بعدش آمده اصلاح می‌شود، چون «لباس تر» هم درست است.
- واژه‌هایی که در کتاب با حرکت آمده‌اند (آخُر، غُرُق) هرگز اصلاح نمی‌شوند، چون بی‌حرکت کلمهٔ دیگری‌اند (آخر، غرق).
- هر قاعده روی متن خودِ کتاب دستور خط اجرا و خطاهای کاذبش رفع شده است.
- هر جا درستی به معنا بستگی دارد («رفت و آمد» ← «رفت‌وآمد» فقط در معنای اصطلاحی؛ «خانهای» که هم «خانه‌ای» است هم «خان‌های»)، فقط گزارش می‌شود و اصلاح خودکار ندارد.
- فهرست واژه‌هایی که کتاب صریحاً پیوسته نوشته (`src/dict/book-joined.json`) بر همهٔ قواعد خودکار مقدّم است.

## داده‌ها

- `src/dict/multi-spelling.json` با `scripts/extract_multi_spelling.py` از فایل docx کتاب ساخته می‌شود (pandoc لازم است). خود کتاب در این مخزن نیست.
- `src/dict/hazm-*.json` (ستاک‌های فعل، صفت‌ها، جفت‌های «بی-») با `scripts/build_hazm_data.py` از داده‌های [Hazm](https://github.com/roshan-research/hazm) (مجوز MIT) ساخته می‌شوند.
- `src/dict/farhang-emlaei.json` با `scripts/extract_farhang_emlaei.py` از PDF فرهنگ املایی ساخته می‌شود. متن PDF با قلم‌های قدیمیِ غیریونیکد است؛ هر گلیف یک‌بار خوانده و بر اساس نام گلیف نگاشت شده، و نیم‌فاصله‌ها از شکل گلیف (آغازی/میانی در برابر پایانی/تنها) دقیقاً بازسازی می‌شوند.
- `src/dict/farhang-v2-overrides.json` و `docs/farhang-conflicts.md` (در ریشهٔ مخزن) با `scripts/check-farhang-conflicts.cjs` ساخته می‌شوند: همهٔ قاعده‌ها روی همهٔ مدخل‌های فرهنگ اجرا می‌شوند و هر جا قاعده‌ای چیزی را عوض کند، شکل ویراست دوم ملاک است؛ به‌علاوهٔ فهرست بستهٔ «هم-» و پسوندهای «-جات، -آسا، -آگین، -باره، -فام، -وش».
- بقیهٔ فایل‌های `src/dict` دستی و از روی فهرست‌های کتاب نوشته شده‌اند.

```sh
python3 scripts/extract_multi_spelling.py کتاب.docx > src/dict/multi-spelling.json
pip download hazm --no-deps -d /tmp/hazm
python3 scripts/build_hazm_data.py /tmp/hazm/hazm-*.whl
pip install pymupdf fonttools
python3 scripts/extract_farhang_emlaei.py فرهنگ.pdf > /tmp/entries.json
python3 scripts/build_farhang_data.py /tmp/entries.json
npm run build && node scripts/check-farhang-conflicts.cjs && npm run build
```
